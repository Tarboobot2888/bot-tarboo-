# TERBOO ARCADE — HTML 3D migration

## Included changes

- All rooms produced by the unified TERBOO ARCADE engine now build a standalone HTML view and attempt the HTML rich-response transport.
- Arcade room delivery no longer generates or attaches PNG/JPEG board images. The WhatsApp-native action buttons, text input path, server-side move validation, room state, AI turns, rewards, and stats remain authoritative.
- The HTML card uses a 3D bevel/glass/neon design system with responsive grids, player chips, state badges, raised tiles, panels, RTL/LTR support, reduced-motion support, and no external resources.
- The live `/play/<token>` website receives a visual 3D polish while preserving the existing server-authoritative action API.
- Legacy Minecraft, Fish It, and Werewolf game messages no longer send image thumbnails/link previews; their existing command/game logic is retained.
- The shared classic quiz engine (`src/lib/terboo-games.js`) also uses 3D HTML question cards. Guess-the-image assets are compressed and embedded inline in the HTML payload when supported; no board screenshots or preview thumbnails are generated by this route. A real quiz asset may still be sent as a compatibility fallback if HTML cannot be relayed.

## Important client limitation

WhatsApp HTML rich-response rendering is an undocumented, client-dependent feature. The payload deliberately does **not** fabricate `botMetadata`, certificate chains, signatures, `trusted_sources`, or a forwarded Meta identity. On clients that do not render the HTML primitive, the bot still sends its native text and real WhatsApp buttons; the HTML card itself is a visual view, not the authority for a move. The game website is the path for fully interactive browser controls.

Set `TERBOO_ARCADE_HTML=off` to disable the experimental rich HTML transport. The default in this patch is `rich`.

## Validation performed for this patch

`node --check` passed for the changed JavaScript/ES module files. The integration test `node tests/terboo-arcade-html.test.mjs` could not start in this source-only environment because the project's dependency `@whiskeysockets/baileys` is not installed here. Rich HTML rendering also needs verification on the actual WhatsApp client; it is not claimed to work on every client from static checks alone.
