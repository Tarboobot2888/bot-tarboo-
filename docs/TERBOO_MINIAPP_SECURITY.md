# TERBOO MINI APPS — نموذج التهديد وحدود الثقة

---

## 1. حدود الثقة

```
┌─ غير موثوق تماماً ─────────────────────────────────────────┐
│ • جسم رسالة واتساب (نص · معرّف زر · رد)                     │
│ • أي شيء يرسله المتصفح: body الطلب · DOM · localStorage     │
│ • قيم URL (الرمز موقّع، لكن ما بعده ليس سلطة)                │
│ • صور/بيانات الأسئلة الخارجية                                │
└──────────────────────────┬─────────────────────────────────┘
                           │ تحقق إلزامي
┌─ موثوق (الخادم فقط) ─────▼─────────────────────────────────┐
│ • m.sender من طبقة واتساب ⇒ actor                           │
│ • حالة الغرفة في engine.js (المصدر الوحيد للحقيقة)           │
│ • legalActions/validateFree/apply/status من العقد            │
│ • serverRng (crypto) · المكافآت عبر progress/repository      │
│ • أسرار القاعدة: arcade:webSecret · arcade:assetSecret       │
└────────────────────────────────────────────────────────────┘
```

**قاعدة واحدة:** لا يحسب العميل نتيجة ولا يمنح مكافأة ولا يحدّد دوراً.
الصفحة تعرض `getView` وترسل `{actionId, payload, nonce, timestamp}` فقط.

---

## 2. هوية الفاعل

| القناة | من أين يأتي `actor` |
|---|---|
| زر واتساب | `m.sender` — **لا** من نص الزر |
| نص/رد | `m.sender` |
| كلام طبيعي | `m.sender` |
| صفحة Mini App | المقعد الذي تطابقت بصمته في الرمز الموقّع |

لا يُقرأ الفاعل من DOM ولا من JSON العميل في أي مسار.

---

## 3. رمز اللعب

```json
{"r":"<roomId>","s":"<sessionId>","f":"<بصمة مقعد معمّاة>","e":<انتهاء>}
```
`HMAC-SHA256(arcade:webSecret).slice(22)` · TTL 6 ساعات · مقارنة **بزمن ثابت** (`timingSafeEqual`).

**البصمة** = `HMAC(secret, "seat:<roomId>:<playerId>")`:
- غير قابلة للعكس ⇒ الرمز لا يحمل رقم هاتف ولا JID ولا معرّفاً قابلاً للقراءة.
  `base64url` ليس تعمية، والرابط يُشارَك في الدردشة ويُسجَّل في المتصفح والوسائط.
- مختلفة لكل غرفة ⇒ لا تربط لاعباً بين غرفتين.
- **ليست رقم مقعد**: مغادرة لاعب قد تُزيح الفهارس فيصير رمز قديم صالحاً لمقعد شخص آخر.

> **تنبيه ترحيل:** رموز صدرت قبل هذا التغيير لا تُقبل (كانت تحمل `p` بالمعرّف الصريح).
> المدة 6 ساعات، والحل أن يعيد اللاعب إرسال أمر اللعبة. موصوف في مستند الرجوع.

## 4. تحقق كل إجراء (`engine.applyAction`)

| # | الفحص | رمز الرفض |
|---|---|---|
| 1 | بنية الإجراء ونوع كل حقل وطوله | `bad-*` |
| 2 | `actionId` يطابق `^[a-z][a-z0-9_.]{0,31}$` | `bad-actionId` |
| 3 | حجم الحمولة ≤ الحد، وعمقها ≤ 3 | `payload-too-large` |
| 4 | **لا حقل قرار خادمي** في الحمولة (`FORBIDDEN_PAYLOAD_KEYS`: winner · score · turn · state · balance · koin · exp · reward · admin · result …) | `forbidden-field` |
| 5 | الجلسة موجودة وتطابق اللعبة | `no-session` · `session-mismatch` |
| 6 | **قفل الغرفة** (`withLock`) — حركتان لا تُطبَّقان على نسخة واحدة | — |
| 7 | المرسل لاعب فعلي غير آلي | `not-a-player` |
| 8 | `messageId` غير مكرر | `duplicate` |
| 9 | `nonce` يطابق النسخة الحالية؛ والقديم يُميَّز عن المختلق | `stale` · `bad-nonce` |
| 10 | انحراف الطابع الزمني داخل الحد | `expired-action` |
| 11 | الدور الحالي | `not-your-turn` |
| 12 | الإجراء ضمن `legalActions` حرفياً، أو يمر من `validateFree` | `illegal` |
| 13 | الحالة ليست منتهية/متوقفة | `finished` · `paused` |

الحالة تُنسخ (`structuredClone`) قبل `apply` فلا تتسخ عند الرفض، ويُبدَّل الـnonce بعد كل قبول.

## 5. سطح HTTP

| الحماية | التفصيل |
|---|---|
| CSP | `default-src 'self'` · `script-src 'self'` · `img-src 'self' data: blob:` · `connect-src 'self'` · `frame-ancestors 'none'` |
| رؤوس | `X-Frame-Options: DENY` · `nosniff` · `Referrer-Policy: same-origin` · COOP/CORP same-origin · `Permissions-Policy` يمنع الموقع والميكروفون والكاميرا |
| CSRF | POST يتطلب `Content-Type: application/json` **و**رأس `X-Terboo-Arcade: 1` ⇒ نموذج من موقع آخر لا يمر (415) |
| المنشأ | `Origin` غريب ⇒ 403؛ لا انعكاس لـOrigin |
| حد معدّل | دلو مستقل لمسارات الأركيد (ألعاب سريعة ترسل حركة كل ~0.4ث) ⇒ 429 |
| حجم الجسم | 8KB لطلبات الأركيد؛ الأكبر يُرفض وقد يُغلق الاتصال |
| إنشاء غرفة من الموقع | جلسة + `X-CSRF-Token` مطابق |
| الصفحة | `Cache-Control: no-store` |

## 6. وكيل الأصول

| الحماية | التفصيل |
|---|---|
| رمز موقّع | `HMAC(arcade:assetSecret)` · TTL ساعتان · مربوط بالجلسة · مقارنة بزمن ثابت |
| **قائمة مضيفات مغلقة** | `ALLOWED_HOSTS` — ليس وكيلاً مفتوحاً. `localhost` و`127.0.0.1` و`169.254.169.254` مرفوضة ⇒ لا SSRF نحو الشبكة الداخلية أو بيانات وصفية سحابية |
| HTTPS فقط | `http:` و`file:` و`javascript:` ترفض عند الإصدار |
| النوع | JPEG · PNG · WebP · GIF فقط. **لا SVG** (ينفّذ سكربت) ولا HTML |
| الحجم والمهلة | 2MB · 8 ثوانٍ · `AbortController` |
| الرؤوس | `nosniff` · `Content-Disposition: inline` · CORP same-origin |
| العميل | `play.js` لا يقبل إلا `^/api/v1/arcade/asset/[A-Za-z0-9_.-]+$` — لا عنوان خارجي ولا `data:` |

## 7. السرية والتسريب

- `publicView` يحذف `jid` و`hostId` و`sessionId` والحالة الخام؛ التسوية بالمقعد لا برقم الهاتف.
- ألعاب الأسئلة: فهرس الإجابة داخلي فقط — العميل يرى الخيارات لا الصحيح منها.
- الألعاب البصرية: العميل يرى رمزاً موقّعاً لا عنوان المصدر.
- الاختيار السري (حجر/ورقة/مقص · الأسطول · الأدوار الليلية) لا يظهر في عرض الخصم.
- لا سرّ ولا جلسة واتساب ولا مفتاح توقيع في أي HTML يصل المستخدم.
- الأسرار تُولَّد مرة وتُخزَّن في القاعدة، ولا تُطبع في رد ولا سجل.

## 8. HTML والقوالب

المدقّق (`validateTemplate`) فحص **بنيوي** لا regex على المستند:
- أسماء الوسوم مقابل `FORBIDDEN_TAGS` (script · iframe · form · input · select · audio · video · object · foreignObject …).
- **أسماء** السمات ⇒ أي `on*` يُرفض. (الفحص القديم كان يطابق ` onerror=` داخل قيمة سمة **مُهرَّبة** فيرفض قالباً سليماً.)
- قيم السمات ⇒ بروتوكولات ممنوعة وموارد خارجية.
- كتل `<style>` وسمة `style` ⇒ `@import` · `expression()` · `behavior:` (الخاصية القديمة فقط، فلا تُطابق `scroll-behavior:`) · `url(http…)`.
- حد 64KB، وحد عدد كتل الأنماط.
- كل نص مستخدم يُهرَّب (`escapeHtml`)؛ الواجهة تستخدم `textContent` لا `innerHTML` لنصوص الخادم.
- لا `eval` ولا تنفيذ كود يرسله المستخدم ولا بناء markup من نص غير معقّم.

## 9. تهديدات مرفوضة صراحةً، ومُختبرة

| التهديد | المنع | الاختبار |

## 10. ما لم يُثبت

- **تصيير HTML المضمَّن على WhatsApp Android** غير مُثبت ⇒ النقل **مطفأ افتراضياً**.
  الترميز وحده مُثبت (round-trip)، وهو لا يكفي لإعلان قدرة.
- **لم يُجرَّب أي مسار على عميل واتساب حقيقي** في بيئة التنفيذ (لا جهاز ولا حساب).
  ما أُعلن «نجح بالاختبار» هو ما شغّلته الاختبارات فعلاً.
- 15 اختباراً كانت فاشلة في خط الأساس ما زالت فاشلة لأسباب خارج نطاق الألعاب
  (أرقام مالك · ترجمات ناقصة في ملفات لم تُلمس · تدقيق تصميم لألعاب قديمة مستقلة).
